# 健身打卡 · AstrBot 插件

把部署在 Cloudflare Workers 的健身打卡日历接进聊天。**纯自然对话，不需要任何斜杠命令。**

## 零配置

装好就能用，`sync_id` 留空即可：

插件会调用 Worker 的 `GET /api/active` 拿到当前活跃口令。这个索引由 Worker 在每次写入时自动登记
（`meta:active`），而你的 App 只需要打过一次卡，索引就已经存在了。

> 口令本质是访问凭证，所以插件不会把它打印在聊天里。如果哪天想显式固定，再往配置里填即可。

## 直接说话就行

| 你说 | 效果 |
| --- | --- |
| 今天练了腿，45 分钟，挺累的 | 记录 今天 / 力量训练 / 45′ / 吃力 |
| 昨天跑步 30 分钟 | 补录到昨天 |
| 前天跑步20分钟加拉伸15分钟 | 一次记两个项目，自动汇总 35 分钟 |
| 我今天练了吗 | 今天状态 + 本周进度 + 连续天数 |
| 这周练了几次 | 本周明细，含逐天打勾 |
| 这个月怎么样 | 本月统计 |
| 最近都练了啥 | 最近几次记录 |
| 今天记错了，取消一下 | 撤销今天的打卡 |
| 恢复一下上周三 | 补录历史（最多回溯 30 天，不能填未来） |

## 设计取舍

**业务逻辑一律不搬进插件。** 打卡规则、多端合并、时长派生全部留在 `store.js` / `worker.js`。
插件只做「取文档 → 调接口」，这样手机 App 和机器人永远同一套口径，不会出现两边数字打架。

**写操作走 `/api/state/:id/mark`。** 由 Worker 在服务端完成读-改-写，
所以机器人打卡不会覆盖别的日期，也不会被手机端正在打开的页面 push 顶掉。

**历史日期有护栏。** 不允许未来日期，最多回溯 30 天，防止模型乱填日期污染数据。

## 依赖的 Worker 接口

- `GET  /api/active`
- `GET  /api/state/:id`
- `POST /api/state/:id/mark`  `{action:"mark"|"unmark", day, name?, mins?, effort?, items?}`
- `POST /api/state/:id/merge`

## 排错

`/健身` 之类命令不再提供，全部走自然语言。如果 AI 没有调用工具，先确认：

1. 配置里 `allow_llm_tools` 是开启的
2. 当前对话使用的模型支持 function calling
